## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Проверка находок:
- I2 подтверждена чтением: Presentation не слушал didBecomeActive и прерывания. Выбрано: плеер следует playing ядра (продолжает), shouldResume не учитывается.
- I3 подтверждена: таймаут бросал до defer, ошибка не кешировалась. I4 подтверждена (queue: nil + общая NSLock вокруг open). Рекомендация ревьюера постить memory warning в свою OperationQueue не помогла бы: post синхронно ждёт наблюдателя; сделано async на глобальную очередь внутри блока.
- I4 (в) таймаут OriginalSize в Go не сделан: после правки натив возвращается ≤30 с и не блокирует другие файлы, хост ждёт участника 20 с (A41) — дополнительный таймаут ничего не меняет для участника.
- I5: сделан вариант (б) + время pending; асинхронная остановка не делалась (по заданию).
- I6: вместо TEST_RUNNER_-переменной — проверка вывода xcodebuild на ' skipped (' при IOS_REQUIRE_PHOTOS=1 (не зависит от передачи переменных в хост).
- I7: Xcode закреплён DEVELOPER_DIR=Xcode_26.6 (env.log не печатал список Xcode — теперь печатает). Устаревшие API не заменены: нужен async-мост.
- I8: кеш кандидатов в Go (вариант б), таймаут Media не сделан (сломал бы первый долгий список).
- I9: ключ PHPhotoLibraryPreventAutomaticLimitedAccessAlert не добавлен: без своего presentLimitedLibraryPicker системный алерт — единственный путь добавить фото при ограниченном доступе.
- I10: классификация в Swift (символьные AVError.Code), URL видео — привязка к показу; три причины network/unsupported/unplayable.
- I11: ios-smoke читает diag.log из контейнера.
- I12: setActive(false, notifyOthersOnDeactivation) при снятии видео.
