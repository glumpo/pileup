## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ревью 2026-11-09, R08 (P1): Create может пройти до регистрации стартового Pull (окно announce) и создать форк при доступном пире. R14 (P2, согласовано): ограниченные линейные повторы подключений, отмена кандидатов при Lost, немедленная остановка на ошибке подлинности.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Первая запись после старта ждёт стартовой проверки известных пиров (включая announce); без пиров или при их недоступности запись не блокируется навсегда
- [ ] #2 Повторы подключения: до 100 с паузой n×10 мс, остановка на ErrCertificate/ErrMembership без Pull, отмена кандидата по Lost, без параллельных циклов от повторных Found
- [ ] #3 Каждая ошибка сначала воспроизведена красным тестом
<!-- AC:END -->

## Implementation Plan

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
R08 подтверждён: при задержанном announce запись проходит сразу (seq 11), после ответа пира Pull получает ErrFork на seq 12, журнал остаётся 11 операций. Красные тесты: TestFirstWriteAfterRestartWaitsForKnownPeer (запись завершилась до стартовой проверки), TestCancelledWriteLeavesStartCheckForOthers (отменённый вызов вернул nil и создал операцию). Исправление: replica.Node.Hold регистрирует ожидание синхронно в start для каждого сохранённого пира; снимается после первого успешного раунда или завершения первой попытки (announce+Pull). TestWriteWithoutPeersIsImmediate и TestUnreachablePeerDoesNotBlockWrites зелёные и до исправления.
