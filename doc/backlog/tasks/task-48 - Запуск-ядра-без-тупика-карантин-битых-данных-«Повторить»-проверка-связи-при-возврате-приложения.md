## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ревью 2026-11-11 (doc/review-2026-11-11/reliability.md R2-01, R2-03, R2-10; diagnosability.md D4): любая ошибка открытия ядра — тупик. Битый cache.db (это только кеш), одна битая БД pile или полный диск блокируют всё приложение: на экране сырой английский текст исключения без кнопок, перезапуск не помогает. Циклы Accept порта 127.0.0.1 не перезапускаются, а /health приложение не использует: на iOS после приостановки возможна мёртвая связь UI с ядром, из которой выходят только убийством приложения. Ошибка рендера вне Boundary роняет release-сборку; паника в обработчике под мьютексом без defer превращается в вечную блокировку.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Повреждённый cache.db откладывается в сторону и создаётся заново; узел стартует, событие в журнале
- [ ] #2 Pile, БД которого не открылась, не мешает запуску и остальным pile: он виден в списке с причиной; остальные работают
- [ ] #3 При сбое запуска экран называет причину по-русски (отдельно — нехватку места), даёт «Повторить» и «Поделиться подробностями»; повтор запускает ядро без перезапуска приложения
- [ ] #4 При возврате приложения на передний план связь с ядром проверяется; если ядро не отвечает, оно перезапускается и приложение продолжает работу с новым портом и токеном без действий пользователя
- [ ] #5 Ошибка рендера любого экрана не роняет приложение: корневая граница с текстом и возвратом к списку pile; мьютексы blob.Get и show.Host.do освобождаются при панике
- [ ] #6 Каждое изменение поведения сначала воспроизведено красным тестом; doc/adr и architecture.md (A54) обновлены
