## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Красные тесты (cbcf88d), на коде до правки:
- TestBrokenItemIsPlannedAgainAfterRecheck — «load after the recheck = [], want [a000]»
- TestInvariantsOverRandomEvents — «waiting [], want [a028]» (модель снимает пометку через Recheck; в модель добавлено действие «время + Recheck», потому что шаги по 0–40 с до пяти минут почти не доходят: без него 3000 проверок противоречия не нашли)
Заглушки в красном коммите: константа Recheck, параметр now у Broken, загрузчик передаёт time.Now().

Реализовано (b7e84d8): broken в планировщике — map id → срок; Broken(id, now) ставит now + Recheck (5 мин). Plan(now) первым делом снимает истёкшие пометки (maps.DeleteFunc), дальше файл планируется как обычный; новая постоянная ошибка ставит пометку снова. Пока пометка действует: файл не планируется и не держит слот источника (Broken сбрасывает отказы источника, как и раньше), не считается ждущим, в Progress идёт как Failed. Между истечением и загрузкой — обычный недостающий файл (в прогрессе ни Done, ни Failed; при недоступном источнике — ждущий). 5 минут выбраны как «несколько минут»: исправленный файл появляется не позже чем через 5 минут, а постоянная ошибка стоит одного запроса раз в 5 минут на файл.

Проверка: gofmt, go vet ./...; go test -race ./prefetch -count=3 и -rapid.checks=3000; ./show и ./httpapi целиком (TestPermanentlyFailingFileDoesNotBlockItsSource по-прежнему видит прогресс [30, 29, 1]); go test -race ./... в core — всё зелёное.

Ограничения: на уровне show повтор через 5 минут не проверяется (реальное время); загрузчик передаёт time.Now() так же, как в Failed. Пауза постоянная, не растёт при повторных ошибках. Пульт (Pins.tsx) перестаёт опрашивать прогресс, когда done + failed = total, поэтому исход повторной проверки увидит при следующем открытии панели. Пометки по-прежнему только в памяти.

Решение для architecture.md: Постоянная ошибка T2 (404, отказ владельца, ошибка своего рендера) помечает файл «битым» на 5 минут (prefetch.Recheck), а не до перезапуска ядра. Пока пометка действует, файл не планируется, не блокирует источник, не считается ждущим и в прогрессе закреплений идёт как failed; затем он снова планируется как обычный, и новая постоянная ошибка ставит пометку снова. Меняет в A26 «помечает только этот файл до перезапуска ядра» и снимает R27 «битые до перезапуска». Почему: временная ошибка рендера или отказ владельца становились постоянными, даже если владелец уже исправил файл («Мелкое» в architecture-review.md). Один повторный запрос раз в 5 минут на файл почти ничего не стоит. TASK-37.
