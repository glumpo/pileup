## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Проход фоновых T1 читает всю проекцию, снимает удержания и вызывает open для T1 каждого чужого файла, в том числе кешированных (замер на x86: ~0,1 с на 600 файлов, на телефоне в разы дольше). Если хоть одна загрузка не удалась, проход повторяется через 1 с — пока у недоступного участника есть незагруженный T1 или пока в pile есть файл с постоянной ошибкой. Такой файл каждый участник запрашивает раз в секунду, и владелец каждый раз пытается его отрендерить, занимая очередь рендера. Н8 в doc/architecture-review.md.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Пока владелец недоступен, его недостающие T1 не запрашиваются чаще, чем меняется его доступность или pile; после его возвращения они загружаются
- [ ] #2 Файл, T1 которого владелец не отдаёт (404 или ошибка рендера), запрашивается повторно не чаще раза в несколько минут
- [ ] #3 Проход, в котором все T1 уже в кеше, не обращается к владельцам и не трогает кеш по каждому файлу
- [ ] #4 Каждое поведение сначала воспроизведено красным тестом
- [ ] #5 doc/adr/cache.md обновлён
<!-- AC:END -->
