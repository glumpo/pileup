## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
iPhone-источник перестаёт отвечать, когда гаснет экран. Пользователь хоста должен понять причину и иметь способ один раз забрать все превью, чтобы дальше не зависеть от этого телефона (architecture.md, 6.3).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 При таймауте источника на хосте показывается подсказка с именем участника и советом разблокировать телефон
- [x] #2 Кнопка «Загрузить всё с участника» загружает весь T2 этого участника, кнопка «Загрузить вообще всё» — весь T2 pile; видео не загружается
- [x] #3 Перед загрузкой показываются оценка объёма и свободное место, во время — прогресс по участникам
- [x] #4 Загруженное кнопками закрепляется и не вытесняется, пока пользователь не снимет закрепление
- [x] #5 Если источник видео недоступен, на экране постер и подсказка, показ можно продолжить
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. core/prefetch: закреплённые недостающие элементы грузятся после окна в порядке хронологии от курсора (без курсора — с начала) с тем же лимитом 5 на источник; Broken(id) — постоянная ошибка файла (нет файла, источник ответил ошибкой, свой рендер не удался) не наказывает источник и больше не грузится; Progress() по источникам для закреплённых (всего/готово/ошибки), Size, Unavailable. Тесты по спецификации и обновлённый property-тест.
2. core/node: закрепления pile на устройстве (piles/<id>.pins.json, по asset_id), свободное место (statfs каталога данных), экспорт ErrRefused для ответа источника ошибкой.
3. core/show: кеш и загрузки вынесены из сессии показа в загрузчик pile на хосте (живёт до Close хоста), сессия только двигает курсор. Закрепление «всё с участника»/«всё» и снятие, оценка (файлы, недостающие, оценка байт по среднему размеру загруженных T2 pile или 400 КБ, бюджет, свободное место, превышение бюджета), прогресс по участникам с причиной ожидания. Подсказки в состоянии показа: участник (имя, платформа), причина unreachable/timeout; запись в журнал (timeout). Видео недоступного источника: на экран уходит постер, video_unavailable в состоянии, Play — повторная попытка, Next работает.
4. core/httpapi + api/openapi.yaml: GET/POST/DELETE /piles/{id}/pins, GET /piles/{id}/pins/estimate; новые поля состояния показа.
5. Тесты на критерии #1–#5 и на постоянно падающий файл; gofmt, go vet, go test -race (повторы), make check.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Начата Go-часть: подсказки при таймауте источника, кнопки «Загрузить всё с участника» и «Загрузить вообще всё» с оценкой объёма, прогрессом и закреплением.

Go-часть сделана (core/prefetch, core/node, core/show, core/httpapi, api/openapi.yaml).
Планировщик: закреплённые недостающие T2 грузятся после окна в порядке хронологии от курсора (дальше — с начала хронологии; без показа — с начала), с общим лимитом 5 на источник. Broken(id): постоянная ошибка файла (у владельца нет файла — 404, владелец ответил ошибкой — ErrRefused, не удался рендер своего файла) — файл больше не грузится до перезапуска ядра и не считается ждущим, источник при этом считается ответившим (сброс отказов). Так один «битый» файл больше не блокирует источник (риск из TASK-15). Progress() по источникам для закреплённых (всего/готово/ошибки), Size, Unavailable.
Хост: кеш и загрузки вынесены из сессии показа в загрузчик pile (show.Host держит по загрузчику на pile до Close; тик раз в секунду), поэтому кнопки работают и без показа, а кеш переживает перезапуск показа. Закрепления хранятся по asset_id в piles/<id>.pins.json (переживают перезапуск; новая ревизия файла остаётся закреплённой, старая вытесняется первой). Закрепляются файлы, которые есть в pile в момент нажатия; добавленные позже — нет. Снятие закрепления оставляет файлы в кеше до вытеснения по бюджету.
Оценка: размер T2 заранее неизвестен — берётся средний размер уже загруженных T2 этого pile, без них 400 КиБ (верхняя граница 6.1); свободное место — statfs каталога данных (linux/android/darwin/ios собираются); over_budget = закреплённое + выбранное (загруженное по факту, остальное по оценке) больше бюджета. Загрузка всё равно идёт и сверх бюджета (A15).
Подсказки: hints в состоянии показа — участники, чьи файлы окна ждут, и владелец недоступного текущего видео: author, name, platform, reason (unreachable — нет соединения синхронизации, timeout — соединение есть, но загрузки падают). Ждущий участник пишется в журнал (kind timeout, peer = author) при появлении.
Видео: если владелец текущего видео недоступен (при переходе) или прокси оригинала через хост вернул 502, экран получает постер (T2, image/jpeg), video_unavailable = true, Playing = false; next/prev работают как обычно; play повторяет видео, когда владелец снова доступен.
HTTP: GET/POST/DELETE /piles/{id}/pins, GET /piles/{id}/pins/estimate; новые поля состояния video_unavailable, hints; код ошибки unknown_member. Host.Close (останавливает показ и загрузчики) вызывается из mobile.Stop.
Тесты: prefetch (закреплённые после окна от курсора и по кругу, лимит 5, не вытесняются сверх бюджета, битый файл не блокирует источник, прогресс; property-тест расширен закреплениями и Broken), node (закрепления переживают перезапуск, свободное место), show (подсказка с именем участника и запись timeout в журнал, «всё с участника» и «вообще всё» с оценкой и прогрессом по ходу, видео не читается; закреплённые не вытесняются при маленьком бюджете и после перезапуска хоста, вытесняются после снятия; постоянно падающий файл не блокирует остальные; постер и подсказка при недоступном видео, показ продолжается), httpapi (эндпоинты, ошибки, токен). Мутации проверены: без Broken тест с битым файлом падает на новых файлах окна; без закрепления в планировщике и без перехода на постер тесты падают.
Риски: причина timeout end-to-end не проверена (нужен зависший, но подключённый источник); постоянные ошибки не повторяются до перезапуска ядра; GET /piles/{id}/pins перечитывает хронологию при каждом запросе; бюджет 1 ГиБ — на каждый pile отдельно.

Go-часть в master, решение A26 записано. Интерфейс (подсказки по hints, кнопки, оценка, прогресс, снятие закрепления, постер недоступного видео) — следующим шагом.

Интерфейс сделан (app/src/Pins.tsx, Remote.tsx, PileScreen.tsx, api.ts).
Пульт: баннер строится по hints, а не по waiting: «Нет ответа от iPhone: Аня. Возможно, погас экран — попросите разблокировать телефон и открыть Pileup.» для unreachable (и неизвестных причин), «Медленно отвечает телефон: Боря. …» для timeout; «iPhone» при платформе ios, иначе «телефон», имя через двоеточие без склонения (стиль A25; прежние строки «Ждём iPhone: Аня» заменены). У каждой подсказки кнопка «Загрузить всё с участника» (доступное имя «Загрузить всё с участника: Аня»). При video_unavailable поверх постера: «Видео недоступно — на экране постер. Попросите разблокировать телефон и открыть Pileup или переходите к следующему файлу.»; «Следующий» и «Воспроизвести» работают как обычно. Внизу пульта «Загрузить вообще всё».
Экран pile: раздел «Загрузка на это устройство» — участники с файлами (author и имя берутся из хронологии, в Pile нет author), у каждого «Загрузить всё с участника», затем «Загрузить вообще всё».
Общая часть (usePins и PinsPanel): нажатие запрашивает оценку и показывает блок подтверждения: «Файлов: 1800, ещё не загружено: 560 (примерно 219 МБ).», «Свободно на устройстве: 5,5 ГБ.» (если известно), при over_budget предупреждение «Не поместится в кеш (1 ГБ): закреплённые файлы всё равно загрузятся и займут место сверх него.», «Начать загрузку» / «Отмена». Размеры в двоичных единицах с русскими подписями (КБ/МБ/ГБ, до 10 — один знак после запятой). Прогресс по участникам «Аня: 1240/1800» (+ «, ошибок: N»), опрос GET /pins раз в секунду, пока экран открыт и загрузка не закончена; «Снять закрепление» у каждого участника и «Снять все закрепления».
Тесты (jest, фейковое ядро): show.test — подсказки по причине и платформе с кнопками, кнопка у подсказки → оценка → подтверждение → POST с member, «Загрузить вообще всё» с пульта → POST {}, видео недоступно — текст поверх постера и переход дальше; pins.test — участник с экрана pile, всё с прогрессом по участникам, предупреждение о бюджете и отмена, прогресс по опросу и прекращение опроса после ухода с экрана, снятие закрепления по участнику и всех.
Риски: экран pile загружает всю хронологию ради списка авторов; в списке есть и сам пользователь (своё устройство в API не отличить); причина pins.reason на экране не показывается.
